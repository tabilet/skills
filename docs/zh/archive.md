# Archive

在干净基线下，把范围较大的现有包快照为一组冻结的、有证据支撑的上下文文件，
然后创建或刷新当前的产品与架构摘要。

在你的项目会话中发送该请求：

| 智能体 | 会话请求 |
|---|---|
| Claude Code 插件 | `/memory-bank:memory-bank-archive` |
| Codex 插件 | `$memory-bank:memory-bank-archive` |
| DSH | `/memory-bank-archive` |

不需要任何参数。你可以描述想要梳理的包或上下文。如果是直接安装到技能目录，
请参见 [调用前缀](installation.md#invoke-a-skill)。

## 何时使用

在 [init](init.md) 之前，当范围较大的现有包需要一次仓库梳理预检时使用。之后，
当发生实质变化的上下文需要后继快照时也可以使用。

Init 会评估是否需要一次 Archive 预检，并解释结果。如果需要，请在回到 Init 之前
显式请求 Archive。小而内聚的包会直接进入初始化，而跨越多个稳定上下文的边界会
先被送到这里。这里刻意不设文件数或行数阈值。自动生成的客户端可能很大但在概念上
很简单；一个支付模块可能很紧凑，但在架构上却很密集。

## 它会产出什么

事实，而不是路线图。归档文件绝不包含可执行的任务状态，也绝不进入状态顺序或
目标顺序。

```text
tabilet/docs/archive-C01.md    公共客户端 API，位于提交 4f8c…
tabilet/docs/archive-T01.md    传输与进程生命周期，位于提交 4f8c…
tabilet/docs/archive-A01.md    产物捕获与存储，位于提交 4f8c…

tabilet/memory-bank/product.md         当前产品与领域摘要
tabilet/memory-bank/architecture.md    当前系统摘要，外加归档注册表
```

对于每个上下文，它确立目的与归属、领域概念与不变量、组件与数据流、公共契约与
依赖、持久化、安全与运行行为，以及该上下文实际是如何验证的。每一条论断都指向
仓库证据。

缺失的测试或相互冲突的文档会被记录为证据缺口。它不会被悄悄转换成一个里程碑。

## 三个阶段

**调研。** 阅读智能体说明、文档、清单、构建与 CI 配置、包边界、入口点、公共
接口、测试和部署文件。选择一个内聚的产品、归属与验证边界。确定基线：Git 存在
时，是完整 `HEAD` 提交处的干净工作区；或者在你接受这种较弱的来源信息之后，
是一个显式标记为 `unversioned` 的快照。

**给出方案。** 展示边界、上下文划分、通道含义、覆盖范围、证据根、后继决策以及
每一项文件操作。在你全部批准之前，不会写入任何内容。

**写入。** 在随附的写入契约下应用已获批准的操作。

## 归档通道

归档文件命名为 `tabilet/docs/archive-<LANE><NN>.md`。字母用于分类稳定的产品
领域或归属上下文；数字是该通道内的快照时间顺序。

归档通道**独立于状态通道**。`archive-T01` 并不意味着 `status-T01`，两者也都不
决定执行优先级。要按持久的上下文来划分，绝不按功能、冲刺、评审发现项、团队
名称、文档类型或源码目录来划分。

覆盖范围分为 `partial`、`blocked` 或 `verified`。当 Archive 是一次必需的 Init
预检时，边界内的每个上下文都必须在初始化继续之前达到 `verified`。

## 冻结

一旦通过验证，归档就冻结在其记录的提交处。之后的代码不会重写它。发生实质变化
的上下文会获得下一个未使用的后继 ID。`product.md` 和 `architecture.md` 继续描述
当前事实。

这一区分在几个月后才显出价值：当前架构告诉智能体现在存在什么，而归档解释在某个
已知基线上确立了哪些内容，且并不假装自己仍然是最新的。

## 它不会做什么

Archive 写入的是事实。它不会创建或修改里程碑、候选方向、状态行、目标输入、提交
或外部状态。一次文件移动，或一次不改变高层事实的内部重构，都不构成创建后继版本
的理由。
