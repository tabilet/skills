# Next

实现并验证记忆库里一个可执行任务，更新记录，再按所适用的策略提交。

在项目会话里发送请求：

| 智能体 | 会话中的请求 |
|---|---|
| Claude Code 插件 | `/memory-bank:memory-bank-next` |
| Codex 插件 | `$memory-bank:memory-bank-next` |
| DSH | `/memory-bank-next` |

不需要参数。用大白话也行：*"tackle next pending item in memory bank"* 一样管用。

如果是直接装到技能目录，请参见[调用前缀](installation.md#invoke-a-skill)。

## 何时使用

已初始化的项目有一个已批准、随时可做的任务时用它。这个请求就在该作用域内授权实现；Next 不会
在每次改文件之前再加一道 Init 式的提案关卡。但遇到缺失的决策、权限或者必需能力，智能体照样
会停下来。

**恢复执行**也要用它。某个状态行已经在进行中，Next 就接着做这一行，不再另挑。

## 一次运行做什么

1. 读 `AGENTS.md`，再按它规定的顺序读记忆库。
2. 以 `milestone.md` 的优先级为准，只挑一个可执行状态行。
3. 把它实现出来。
4. 跑 `tech-stack.md` 里写明的验证命令。
5. 更新该状态行，以及所有事实发生变化的记忆库文件。
6. 按所适用的提交策略，提交这一行的工作。

通常的策略是，一个状态行对应一次提交。如果存在主导的显式提交策略，这一点可以改变，
`tabilet/GOAL.md` 运行内部的策略也算。里程碑是评审单位。

## 状态标记

| 标记 | 含义 |
|---|---|
| `[ ]` | 待处理 |
| `[+]` | 已完成 |
| `[~]` | 进行中 |
| `[!]` | 已阻塞 |
| `[X]` | 已取消 |
| `[-]` | 已关闭的历史证据 |

`[-]` 行可能是已经用掉的失败尝试，也可能是为审计留下的、被取代的状态行。它永远不会重试，
也不挡它已获接受的继任行。备注里要写明用掉的是哪次尝试，以及接替它的是哪一行。

!!! warning "反引号不能省"
    标记要严格照上表写：`` `[ ]` ``，而不是 `[ ]`。当前的 API 运行器遇到格式错误的标记，
    会以 **exit 11** 和 "unknown or non-backticked state marker" 这条消息拒绝。较早的运行器
    会静默跳过这样的行，然后像已经完工一样退出。所以除了看行的语法，还要看单独安装的那个
    运行器是什么版本。

比如，任务表格里出现的就是下面这样，反引号要原样照写：

```markdown
| Item | State | Notes |
|---|---|---|
| Add quantity validation | `[ ]` | Verify zero and multi-unit orders. |
```

现有项目如果用别的布局或标记约定，改动之前先看清楚。仪表盘报的警告可能表示旧格式，也可能只是
解析器的限制。永久 ID 不要改名，也别拿不认识的语法去猜任务结果；先用 [Upgrade](upgrade.md)
对一下规则。

## 只允许一个进行中的状态行

整个活跃状态台账里，普通状态行最多只能有一行是 `[~]`，也可以是零行。有的话先接着它做，再把
下一个挑出来。API 运行器会在第一次网络调用之前把这条卡住。

调用某个运维启动器之前，它确切对应的授权操作行必须已经是 `[~]`。这个标记只记录你选中了哪一
行，从来不代表你有权改动外部状态。

## 修正当前事实

某次实现把当前的产品事实或架构事实写错时，同一个任务里就把它改回来，哪怕后面还排着一个文档
任务。中间这段时间，记忆库不允许是错的。

## 里程碑收尾

某一状态行是它里程碑里最后一个没做完的项时，Next 会先按 `milestone.md` 跑里程碑评审，再继续
往下做。最初的完整评审算第 1 轮；每修完一个 P1、P2 或更高严重度的问题，都要验证，然后对整个
里程碑再完整评审一遍。必须十轮之内拿到一次干净通过，而且计数器跨会话、跨评审者一直保留。

关闭里程碑时还要判断 `tabilet/evolution/` 需不需要新版本。只有产品方向、架构边界、里程碑目标
或公共契约真的变了，才值得加一个。
