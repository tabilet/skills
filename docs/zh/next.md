# Next

实现并验证记忆库里一个可执行任务，更新记录，再按所适用的策略提交。

在项目会话里发送请求：

| 智能体 | 会话中的请求 |
|---|---|
| Claude Code 插件 | `/memory-bank:memory-bank-next` |
| Codex 插件 | `$memory-bank:memory-bank-next` |
| DSH | `/memory-bank-next` |

可选参数为 `--email ADDRESS`，也可明确指定 `CORRECTIVE_PLANNING` 策略。用大白话也行：*"tackle next pending item in memory bank"* 一样管用。

如果是直接装到技能目录，请参见[调用前缀](installation.md#invoke-a-skill)。

## 何时使用

已初始化的项目有一个已批准、随时可做的任务时用它。这个请求就在该作用域内授权实现；Next 不会
在每次改文件之前再加一道 Init 式的提案关卡。但遇到缺失的决策、权限或者必需能力，智能体照样
会停下来。

**恢复执行**也要用它。某个状态行已经在进行中，Next 就接着做这一行，不再另挑。

## 一次运行做什么

1. 读 `AGENTS.md`，再按它规定的顺序读记忆库。
2. 以 `milestone.md` 的优先级为准，只挑一个可执行状态行。
3. 把它实现出来。
4. 跑 `tech-stack.md` 里写明的验证命令。
5. 更新该状态行，以及所有事实发生变化的记忆库文件。
6. 按所适用的提交策略，提交这一行的工作。

通常的策略是，一个状态行对应一次提交。如果存在主导的显式提交策略，这一点可以改变，
`tabilet/GOAL.md` 运行内部的策略也算。里程碑是评审单位。

## 状态标记

| 标记 | 含义 |
|---|---|
| `[ ]` | 待处理 |
| `[+]` | 已完成 |
| `[~]` | 进行中 |
| `[!]` | 已阻塞 |
| `[X]` | 已取消 |
| `[-]` | 已关闭的历史证据 |

`[-]` 行可能是已经用掉的失败尝试，也可能是为审计留下的、被取代的状态行。它永远不会重试，
也不挡它已获接受的继任行。备注里要写明用掉的是哪次尝试，以及接替它的是哪一行。

!!! warning "反引号不能省"
    标记要严格照上表写：`` `[ ]` ``，而不是 `[ ]`。当前的 API 运行器遇到格式错误的标记，
    会以 **exit 11** 和 "unknown or non-backticked state marker" 这条消息拒绝。较早的运行器
    会静默跳过这样的行，然后像已经完工一样退出。所以除了看行的语法，还要看单独安装的那个
    运行器是什么版本。

比如，任务表格里出现的就是下面这样，反引号要原样照写：

```markdown
| Item | State | Notes |
|---|---|---|
| Add quantity validation | `[ ]` | Verify zero and multi-unit orders. |
```

现有项目如果用别的布局或标记约定，改动之前先看清楚。仪表盘报的警告可能表示旧格式，也可能只是
解析器的限制。永久 ID 不要改名，也别拿不认识的语法去猜任务结果；先用 [Upgrade](upgrade.md)
对一下规则。

## 只允许一个进行中的状态行

整个活跃状态台账里，普通状态行最多只能有一行是 `[~]`，也可以是零行。有的话先接着它做，再把
下一个挑出来。API 运行器会在第一次网络调用之前把这条卡住。

调用某个运维启动器之前，它确切对应的授权操作行必须已经是 `[~]`。这个标记只记录你选中了哪一
行，从来不代表你有权改动外部状态。

## 操作权限 {#action-authority}

读取所属里程碑的可选 `AUTHORIZATION_REQUIREMENTS`，按当前具体的人类请求检查受保护操作。
声明、提议授予和状态文字不能证明批准。普通本地工作不授权安装、提权、任意网络活动、远程命令或真实浏览器操作。
声明为 `fixture` 环境的浏览器要求可以使用 goal 策略；其他浏览器环境仍需明确授权。
先只读解析精确目标；复用有效授予，范围变化时重新批准。

goal 内使用收窄后的有效授予，并保留提交与外部修改限制。goal 外由当前单行请求和项目规则约束，
以前运行的授予不自动延续。必要操作未执行时不能收尾。详见[授权指南](goal.md#authorization-requirements-and-grants)。
缺少字段不增加权限或自动迁移；宿主与工具限制仍有效。Python API 路径不消费这些授予。

## 修正当前事实

某次实现把当前的产品事实或架构事实写错时，同一个任务里就把它改回来，哪怕后面还排着一个文档
任务。中间这段时间，记忆库不允许是错的。

## 昂贵检查 {#expensive-checks}

有些行的验收依赖昂贵或受保护的检查。对这些行，运行遵循项目的验证尝试关卡：

- 在能复现失败的最便宜环境中诊断；
- 执行所有相互独立的用例；
- 持久记录尝试次数；
- 同一阶段连续失败三次，或失败发生在里程碑自身范围之外时，停下来询问你。

详见 [goal 指南](goal.md#expensive-checks-and-the-attempt-gate)。

## 修复前置条件与批准提醒邮件 {#corrective-prerequisites-and-approval-email}

`CORRECTIVE_PLANNING: confirm` 是默认值。人类批准 `auto` 后，Next 可在所选任务的原交付目标、
已批准所属仓库、操作授予及明确限额内，准备并检查必要修复方案，调整待处理工作或创建修复里程碑。
只完成这些前置条件后返回原任务，保留中断工作、身份及评审证据。新权限、扩大范围或提高限额仍需批准。
详见[常设纠正规划](goal.md#standing-corrective-planning)。

激活修复行前，把中断的 `[~]` 行改为 `[!]`，记录前置条件 ID、批准来源和恢复条件。
所有前置条件验收且全部阻断解除后，用同一批准恢复为 `[~]`。恢复时优先找回同一链路。
保留未完成实现；重叠修改无法安全分离时暂停。修复不能降低验收或取消未履行义务，
修复里程碑的评审不能替代或重置原里程碑的评审门槛和计数器。

需要批准时，每个请求发送一次邮件：

```text
$memory-bank:memory-bank-next --email abc@def.gh
```

参数为本次运行及恢复选择一个收件人；新调用省略参数就不发邮件。使用正常技能调用前缀。
先[配置 Cloudflare 发送](installation.md#approval-email-setup)。发送器只在本地检查配置，发送简短、
已清理的摘要，并抑制重复或不确定的尝试。子智能体向所有者报告需求。投递不授予批准；发送不可用时，
原批准暂停保持不变。宿主原生工具批准以及 Python API 运行器或控制器调用不属于本功能。

## 里程碑收尾

某一状态行是它里程碑里最后一个没做完的项时，Next 会先按 `milestone.md` 跑里程碑评审，再继续
往下做。最初的完整评审算第 1 轮；每修完一个 P1、P2 或更高严重度的问题，都要验证，然后对整个
里程碑再完整评审一遍。必须十轮之内拿到一次干净通过，而且计数器跨会话、跨评审者一直保留。

关闭里程碑时还要判断 `tabilet/evolution/` 需不需要新版本。只有产品方向、架构边界、里程碑目标
或公共契约真的变了，才值得加一个。
