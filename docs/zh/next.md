# Next

实现并验证一个可执行的记忆库任务，更新它的记录，并按所适用的策略提交。

在项目的会话中发送请求：

| 智能体 | 会话中的请求 |
|---|---|
| Claude Code plugin | `/memory-bank:memory-bank-next` |
| Codex plugin | `$memory-bank:memory-bank-next` |
| DSH | `/memory-bank-next` |

不接受参数。直接用大白话也可以：*"tackle next pending item in memory bank"* 同样能完成任务。

如果是直接安装到技能目录，请参见[调用前缀](installation.md#invoke-a-skill)。

## 何时使用

当已初始化的项目有一个已批准、可供执行的任务时使用它。该请求在这一范围内授权实现；Next 不会
在每次编辑文件之前再加一道 Init 式的提案门禁。但智能体仍会因缺失的决策、权限或所需能力而停下。

也用于**恢复执行**。如果某一行已经处于进行中，Next 会恢复它，而不是另选一行。

## 一次运行做什么

1. 读取 `AGENTS.md`，然后按它指定的顺序读取记忆库。
2. 在 `milestone.md` 优先级的指导下，准确选择一个可执行的状态行。
3. 实现它。
4. 运行 `tech-stack.md` 中指定的验证。
5. 更新该状态行，以及所有事实发生变化的记忆库文件。
6. 按所适用的提交策略提交该行的工作。

通常的策略是一次提交对应一个状态行。主导的显式提交策略（包括 `tabilet/GOAL.md` 运行内部的
策略）可以改变这一点。里程碑是评审的单位。

## 状态标记

| Marker | Meaning |
|---|---|
| `[ ]` | 待处理 |
| `[+]` | 已完成 |
| `[~]` | 进行中 |
| `[!]` | 已阻塞 |
| `[X]` | 已取消 |
| `[-]` | 已关闭的历史证据 |

`[-]` 行是被消耗掉的失败尝试，或是为审计而保留的被取代状态行。它永远不会被重试，也不会阻塞
其已获接受的继任行。它的备注会写明被消耗的尝试以及取代它的继任行。

!!! warning "反引号是必需的"
    请严格按照上表的样子书写标记：`` `[ ]` ``，而不是 `[ ]`。当前的 API 运行器会以 **exit 11**
    和 "unknown or non-backticked state marker" 这条消息拒绝格式错误的标记。较早的运行器会
    静默忽略这样的行，并像工作已经完成一样退出，因此除了检查行的语法，还要检查单独安装的
    运行器版本。

例如，任务表格中出现的就是下面这些字面反引号：

```markdown
| Item | State | Notes |
|---|---|---|
| Add quantity validation | `[ ]` | Verify zero and multi-unit orders. |
```

如果既有项目使用其他布局或标记约定，请先检查再改动。仪表盘警告可能表示旧格式或解析器的限制。
不要重命名永久 ID，也不要从无法识别的语法推断任务结果；请先用 [Upgrade](upgrade.md) 比较规则。

## 只允许一个进行中的状态行

在整个活跃状态台账中，可以有零个或一个普通状态行为 `[~]`。在另选一行之前，先恢复它。API 运行器
会在第一次网络调用之前强制执行这一点。

在调用某个运维启动器之前，它确切对应的授权操作行必须已经是 `[~]`。该标记记录的是选择，
绝不授予外部变更权限。

## 修正当前事实

当某项实现使当前的产品或架构事实失效时，同一个任务就要修正它，即使之后还存在一个文档任务。
不允许记忆库在这段时间里保持错误。

## 里程碑收尾

当某个状态行是其里程碑中最后一个未完成项时，Next 会先运行 `milestone.md` 中的里程碑评审，
然后再继续。最初的完整评审是第 1 轮；每一项 P1、P2 或更高严重度的修复都要经过验证，并随后
对整个里程碑再做一次完整评审。必须在十轮之内获得一次干净通过，而且计数器会跨会话、跨评审者
持续保留。

收尾里程碑时还会询问 `tabilet/evolution/` 是否需要新版本。只有产品方向、架构边界、里程碑目标
或公共契约发生真正的变化，才值得新增一个版本。
