# Upgrade

## 将 v1.5.0 项目迁移到 v2 {#migrate-a-v150-project-to-v2}

v2 把 `AGENTS.md` 保留在项目根目录，并把 Memory Bank 文件移动到 `tabilet/` 下：
`GOAL.md`、`memory-bank/`、`evolution/`、归档以及已退役的历史。其他项目文档仍留在
根目录。安装 v2 绝不会移动这些文件，而 v2 技能和 API 运行器在遇到旧版或混合布局
时会停止。v2 的 DSH 侧边栏可以以只读方式显示 v1.5.0 项目，并给出迁移警告。

使用 Upgrade 技能随附的标准库命令，或 v2 源码检出中的同一个文件。请从已提交且
干净的 Git 工作区开始：

```bash
python3 /path/to/skills/skills/memory-bank-upgrade/migrate-v1.5-to-v2.py /path/to/project
python3 /path/to/skills/skills/memory-bank-upgrade/migrate-v1.5-to-v2.py /path/to/project --apply
```

第一条命令只预览文件操作。`--apply` 会移动文件、更新需要维护的说明和索引、逐字节
保留冻结归档和退役记录，并让差异保持未提交以便评审。它会报告其他项目文档中的路径
引用，供人工评审。它还支持全部退役的项目、仅归档的预检、缺失或自定义的 goal 协议，
以及本地策略。对于未修改的 v1.5.0 `GOAL.md`，它会把那一处路径示例更新为 v2 的位置。
自定义的 `GOAL.md` 保持逐字节不变，并且始终会被标记出来，要求人工检查路径。

如果被中断，请用 `--resume` 运行同一条命令。在继续之前，它会检查位于受跟踪项目
文件之外的临时日志、Git `HEAD`，以及每个计划处理的文件哈希。无法解释的部分布局、
符号链接或目标冲突都会停止并要求人工修复。一旦完成，重复运行不会产生任何改动。

在评审差异和项目检查之后，按照你项目的常规策略提交它。如果工作流规则也需要更新，
请把下文的 Upgrade 作为一次单独的获批合并来使用。

## Upgrade 工作流规则 {#upgrade-workflow-rules}

通过获批的合并来升级现有记忆库的工作流规则，同时保留项目计划、本地策略和历史。

在对应项目的会话中发送该请求：

| 智能体 | 对话请求 |
|---|---|
| Claude Code 插件 | `/memory-bank:memory-bank-upgrade` |
| Codex 插件 | `$memory-bank:memory-bank-upgrade` |
| DSH | `/memory-bank-upgrade` |

参数：可选，即你想要采用的工作流变更。

如果是直接安装到技能文件夹，请参见[调用前缀](installation.md#invoke-a-skill)。

## 何时使用它

在安装更新的技能之后，当你希望现有项目采用新的工作流规则时使用它。

项目必须已经具备里程碑/状态运行器；一个拥有有效索引历史的全部退役项目同样符合
条件。在应用获批的升级之前，请暂停同一账本上的其他执行。

安装更新的技能无法安全地重写每个使用旧版本的项目。这些项目有自己的命令、策略、
计划和历史。**安装永远不会迁移项目。** 这个技能才是采用发生的途径，而且只有在你
批准之后才会进行。

## 三个阶段

**检查与比较。** Upgrade 会把项目已采用的工作流与技能内随附的参考模板进行比较。
有了这个包，检查目标时无需检出，也无需网络访问。它会找出缺失的规则、兼容的本地
等价项、有意的排除项，以及需要你做出决定的冲突。

**提出方案并获得批准。** 它会给出具体的文件操作——聚焦于章节的差异，而不是重述
整份文档——然后等待。

**应用并验证。** 在获得批准后，它应用作用域内的合并，并验证保留确实生效。

## 一个有用的请求

```text
Use memory-bank-upgrade to compare this project's workflow with the bundled
contract. Preserve our plans, local policies, task states, IDs, review counts,
and history. Show the complete proposed file changes before writing.
```

## 哪些内容会被保留

任务状态、永久标识符、本地策略、评审计数器、自定义 goal 协议、已完成的证据以及
冻结历史。已经兼容的项目完全不需要任何变更。

## 升级不是什么

升级采用**运行规则**。它不会作为附带效果去初始化项目、实现工作、提交或退役里程碑。

退役较旧的里程碑是独立的工作，需要自己的作用域和关闭证据。单独安装的 API 运行器
需要自己进行兼容性检查或更新。

## 采用长期记忆

对于已有数月历史的项目，这是最重要的技能，因为 `lessons.md` 和里程碑退役正是通过
它进入一个早于它们的项目。

现有项目需要显式采用。不存在自动的批量迁移，并且退役遵守每一种提交策略。

## 如果 DSH 报告兼容性警告

即使仪表盘无法读取全部记录，你也可以准备一个 Upgrade 请求。
**Insert into empty draft** 只会准备文本；发送它只是要求智能体检查并提出变更。
它并不批准合并。

把警告一并放进对话：侧边栏会把它们与请求文本分开显示。在提出修正方案之前，要求
智能体区分不受支持的旧语法和真正的账本冲突。保留 ID、状态、备注、评审证据和历史；
不要为了消除警告而批量重写它们。
